## Lessons Learned

- When a compatibility/tolerance footnote is already sitting in text you've read this turn, do the percentage math against it *before* presenting a mismatch as a finding — a citation you paraphrased is not the same as a citation you computed against.
- Before designing a multi-step plan around an MCP file-management tool's assumed capabilities (move, delete, batch update), spend one cheap throwaway call testing the riskiest assumption (e.g., does `copy_file` work on a folder?) — it's far cheaper than discovering the gap mid-plan.
- Any inline-content file upload path (base64 into a tool call) has a practical ceiling around 100–200KB before token cost and corruption risk outweigh the convenience; establish "the user uploads directly" as the default for anything larger, and apply that default the *first* time the question comes up in a session, not the second.
- In documents that mix computed, assumed, and genuinely-unknown quantities (BOQs, technical takeoffs), an explicit status column (FIRM / SURVEY-DEPENDENT / TBC / H-ALLOWANCE) is worth more to the recipient than either a fabricated plausible number or a silently omitted line — both of the latter cost more trust when discovered than an honest "don't know yet."
- When a user corrects a technical claim by citing a specific source you already had access to, the right response is to redo the calculation from that source in front of them (show the math), not just accept the correction verbally — it rebuilds confidence faster and catches whether the correction itself needs any refinement.
