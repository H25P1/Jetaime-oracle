## Honest Feedback

**Friction 1 — Google Drive tool result overflow.** The first `list_recent_files` call returned 113K characters and exceeded the tool's token limit, dumping to a file I then had to parse with a Python script via Bash rather than reading directly. `excludeContentSnippets: true` on the retry fixed it, but I only learned that parameter existed by re-reading the tool schema after the failure — worth remembering for next time this comes up.

**Friction 2 — parentId enumeration required many round-trips.** Google Drive's `search_files` only supports one `parentId` per query, and the folder tree was 4 levels deep — I ended up making ~14 sequential/parallel search calls just to map the structure before any content reading started. There's no recursive-list option in the tool, so this overhead is structural, not a mistake, but it did stretch the "just look at Drive" ask into a much longer exploration phase than H likely expected when asking the simple question.

**Friction 3 — AskUserQuestion tool rejected a hand-typed JSON payload once.** I tried calling it with a raw JSON string wrapped in `{"raw": "..."}` (a malformed invocation) and got an InputValidationError, had to retry with proper structured parameters. Minor, cost one wasted round-trip, self-corrected immediately.

## Lessons Learned

- When a skill script prescribes an external-facing action (posting to a shared repo/tracker owned by someone else), verify current convention against live primary sources before executing it — skill docs can lag behind what a community actually does, and the gap is only visible if you actually read real recent examples instead of trusting the script.
- Before committing to reading many external documents (Drive, wikis, large repos), finish enumerating the full scope first and report real counts to the human before deep-reading — "study this folder" can hide 10x more content than the first listing suggests, and scoping after full enumeration prevents both under- and over-delivery.
- When fanning out parallel subagents against a third-party/interactively-authenticated tool (Drive, browser, etc.), send one cheap probe agent first to confirm the tool is reachable from a subagent context before launching the full fan-out — a failed assumption costs 1 agent instead of N.
- When output content mixes public-safe and commercially/personally sensitive material, decide the write destination (public vs. private repo) before writing anything, and leave only a one-line pointer in the public location — deciding this after the fact risks a rewrite or, worse, a leak.
