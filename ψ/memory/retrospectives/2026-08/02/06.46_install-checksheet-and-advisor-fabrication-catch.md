## Honest Feedback

**Friction 1 — Drive full-text search syntax is unforgiving and cost several wasted calls.** `search_files` rejected a bare `Solar PPM` query with "Unsupported query field," and `fullText contains 'PPM'` returned unrelated Rust crate build artifacts before I found the right phrasing (`fullText contains 'Antai' and fullText contains 'installation'`). Each failed attempt was a full round-trip against a large personal Drive with lots of noise (dev tooling, unrelated project files) — expensive relative to the information gained.

**Friction 2 — read_file_content on scanned PDFs returns almost nothing useful, silently.** `Antai_Mounting_Catalog.pdf` came back with only cover-page OCR ("Λ CPP IFC D Intertek CE TUV NORD") — no error, no "this is a scan" flag, just a near-empty string that could be mistaken for "the document has no relevant content" if not cross-checked. This is the second time this session pattern showed up (the BOQ Conduit work earlier hit the same wall with the TF catalog). It's worth a standing note rather than re-discovering it each time.

**Friction 3 — grepping a live JSONL transcript for verification is effective but manual and slow.** Confirming/refuting the advisor's torque claims took four separate grep passes with increasingly specific patterns before landing on the right search terms (`N[·.]m`, `[Tt]orque`, literal number-range patterns). It worked, and it was the right call given the stakes, but there's no faster path available right now than iterating regex against a multi-megabyte JSONL file by hand.

## Lessons Learned

- **`advisor()` (or any second-opinion model) can fabricate specific, attributed-sounding facts with high confidence — verify numeric/citation claims against primary sources before they go into any deliverable someone will act on physically, not just financially.** The tell here wasn't hedging language; the advisor stated the numbers as things "you read directly" with full confidence. Confidence of phrasing is not evidence of grounding. When a claim is checkable (a transcript, a file, a datasheet), check it before repeating it — this generalizes past this one advisor call to any second-opinion or delegated-research input.
- **"I fixed the local copy" and "I fixed the delivered artifact" are different claims — don't let completion language conflate them.** When a deliverable is uploaded/transformed/converted between a local working file and what the recipient actually receives (CSV → Google Sheet conversion, in this case), verify the *delivered* copy before declaring done, not the source file that produced it. A conversion step is a place bugs hide silently.
- **When extracting text from scanned/image-heavy PDFs via automated tools, treat a suspiciously short or generic result as "extraction likely failed," not "document has little content."** Cross-check with a differently-scoped read or an explicit note to the user that the source may need manual review, rather than silently treating thin output as ground truth.
